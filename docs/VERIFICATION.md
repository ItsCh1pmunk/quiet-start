## 代码检查与修复

v1.0.0 已通过独立审查，修复过权限、安全 DOM、地址过滤、设置并发与图标加载方面发现的问题。v1.1.0 在该基础上更新视觉与快速文件夹选择，并使用下表中的真实浏览器场景重新验证。此前修复包括：

- 全对象保存造成的多标签页不同字段互相覆盖：改为各设置字段独立键写入，保持跨页变更监听。
- 写入后旧快照造成的界面回滚：直接依赖变更事件更新，不再用全量读取覆盖已知状态。
- 初始化异步读取与外部变更的竞态：缓存读取期间的变更，合并时新事件优先于旧快照。
- `hidden` 与延迟图片加载相互等待：图片保留实际布局尺寸，以透明度等待，加载成功再隐藏字母。

v1.1.0 的独立复审发现并修复了顶部下拉显示临时浏览文件夹、但该来源尚未保存的问题。两个选择器现统一绑定已保存来源；真实浏览器回归测试已覆盖临时进入子文件夹后将其保存为默认来源的完整流程。复查未发现阻塞问题。

运行时代码没有书签写入调用、`fetch`、XHR、WebSocket、遥测或远程资源。仅申请 bookmarks、storage、favicon 三个 API 权限；未申请主机权限或 tabs/history；未配置 service worker、内容脚本或公开资源。浏览器测试中的书签创建和故障注入仅用于临时配置的验证。

## 验证范围与限制

- 已实际加载扩展；没有替用户安装到日常 Chrome 配置。日常安装步骤在 [Mac 安装教程](INSTALL-MAC.md)。
- 测试使用 Chrome for Testing，未逐一覆盖历史 Chrome 104+ 版本、企业策略环境、Chrome 商店审核或隐身模式。
- 主题自动跟随是通过浏览器的系统主题媒体特性验证；没有修改用户 macOS 的全局外观设置。
- 导入开始/结束和子项重排事件已检查监听注册；没有通过 Chrome 原生文件导入对话框逐项操作验证。改名、创建、删除、移动已使用真实 API 验证。
- 无外部页面请求的结果针对扩展测试页面与本机测试站点。Chrome 自身的同步、遥测和其他浏览器后台请求属于浏览器设置范围，无法通过该测试断言全浏览器绝对零联网。
- 全部用户设置存入 `chrome.storage.local`；Chrome 自身可能已同步用户书签，本扩展不启用也不关闭 Chrome 同步。
